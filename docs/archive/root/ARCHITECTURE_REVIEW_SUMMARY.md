## 关键设计决策

### 通用架构层面

| 决策点 | 选择 | 理由 |
|---|---|---|
| 通信协议 | HTTP + Redis | gRPC 对低频控制无明显收益，HTTP 易调试 |
| 数据粒度 | 1s Bar（行情层聚合） | 策略最快需求 1s，消息量降低百倍 |
| 回测模式 | 行情层 replay + 策略识别模式 | 策略代码零改动，执行层切换清晰 |
| K 线来源 | Binance WS 直接订阅 | 简单，不需要从 aggTrade 重建 |
| Redis 保留策略 | K 线只保留 latest，1s Bar 不持久化 | 最小化内存（< 200 KB），策略自维护窗口 |
| 订阅注销 | 支持指定 symbols 或 all=true，内部计数 | 多进程安全，最后取消才关闭 WS |
| 大周期数据 | V1 不实现，V2 优先 DuckDB 直读 | 逼空策略只需 1s Bar，按需扩展 |

## 止损策略的核心创新

**问题**：固定价格止损（如入场价 +3%）无法适应清算狂热期的脉冲行情，容易被秒扫。

**解决方案**：时间衰减止损 + 形态动态判断

```
开仓后 0-90 秒：禁止固定价格止损（允许任意脉冲）
       ↓
开仓后 90-300 秒：止损距离从 +15% 快速衰减到 +5%
                  形态判断阈值宽松（动能 > 0.3%、横盘 < 0.5%）
       ↓
开仓后 300-900 秒：止损距离从 +5% 缓慢衰减到 +3%
                   形态判断阈值收严（动能 > 0.15%、横盘 < 0.3%）
       ↓
开仓后 900 秒以上：固定 +3% 止损
                   形态判断最严格（动能 > 0.1%、横盘 < 0.2%）
```

**关键优势**：
- 初期极宽松，避免被正常脉冲扫掉
- 随时间收紧，长时间不回落时收严风险
- 形态判断提前识别"不是插针"，不等固定价格

**所有阈值均为候选值**，需通过历史回测样本的分位数分析标定后冻结。
