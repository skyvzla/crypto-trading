# Web 功能与信息架构规划

状态：首期已实施（2026-08-16）；本文同时记录已确认的产品边界、当前实现和后续数据依赖。

## 1. 目标

Web 应围绕日常运行、交易复盘、策略准入和基础数据组织功能，而不是把每个统计指标都做成
一级菜单。页面需要让用户快速回答以下问题：

- 策略、账本、行情和执行链路当前是否正常；
- 当前持仓、订单和已完成交易发生了什么；
- 策略长期表现如何，问题来自哪些交易对或分类；
- 一个交易对为什么全局或对某个策略不可交易；
- Binance Category/Subcategory 及交易对关联当前同步到了什么状态。

首期保持 KISS：复用已有账本、回测和准入能力，不引入登录权限、策略参数热更新、复杂规则
编辑器或高级风险限额。

## 2. 已确认的产品决策

1. 收益日历不并入绩效分析。运行总览展示当月缩略日历，点击后进入独立完整日历页；完整页
   不额外占用侧栏一级菜单。
2. 分类管理统一展示 Category 和 Subcategory，但分类事实及交易对关联由程序同步，Web 不提供
   人工创建、重命名、移动或删除。
3. 策略风控首期只承接按策略配置的 Category/Subcategory 准入开关，保持 D-031 的可选黑名单
   语义；不加入策略参数、高级风险限额或复杂审批流。
4. 交易对管理只负责交易对事实、生命周期和全局准入，不再包含策略分类页签。
5. 胜率与盈亏比保留为绩效诊断指标，不再作为独立一级菜单，也不作为自动交易或上线门槛。

本文中的“策略开关”指选定策略下的分类准入开关。当前没有由 Web 控制策略进程整体启停的
账本接口，首期不新增该能力。

## 3. 功能调整与当前状态

| 原入口 | 调整结果 | 当前实现 |
|---|---|---|
| 运行总览 | 保留并完成 | 已展示账本、策略状态、运行指标、当月收益日历和明细下钻 |
| 收益日历 | 首页摘要 + 独立完整页 | 已按 Asia/Shanghai 的 Campaign 闭合日聚合，不占侧栏一级菜单 |
| 持仓 | 扩展为“持仓与订单” | 已提供当前持仓、活动订单和历史订单服务端分页查询 |
| 成交与买卖点 | 改为“成交复盘” | 已按 Campaign 聚合 fills、展示账本 PnL 和审计时间线；实盘 K 线暂不可用 |
| 胜率与盈亏比 | 并入“绩效分析” | 已按已结束 Campaign 计算胜率、盈亏比、期望值和 Profit Factor |
| 交易对统计 | 并入“绩效分析” | 已提供交易对、Category、Subcategory 和方向分解 |
| 回测复盘 | 保留 | 继续复用既有研究、报表、收益回放、交易与 K 线接口 |
| 交易对管理 | 拆出策略准入 | 只保留交易对事实、生命周期和全局准入 |
| Subcategory 管理 | 改为“分类管理” | 只读展示 Category/Subcategory、关联交易对和同步状态 |

## 4. 目标导航

侧栏使用分组标题和最多两层结构：

```text
运行中心
  运行总览
  持仓与订单
  成交复盘

分析复盘
  绩效分析
  回测复盘

策略与风控
  策略风控

基础数据
  交易对管理
  分类管理
```

收益日历保留独立路由，但从运行总览进入，不在侧栏重复占位。审计记录、交易对详情和单笔
K 线复盘使用页签、抽屉、弹窗或下钻路由，不新增一级菜单。

## 5. 页面范围

### 5.1 运行总览

运行总览是默认首页，优先展示需要立即关注的信息：

- 当前环境明确标识为 testnet 或 live；
- 账本数据库健康、策略运行状态、行情连续性和执行门禁分开展示；
- 今日已实现净 PnL、浮动 PnL、手续费、当前持仓和活动订单；
- 最近信号、最近成交、最后心跳和异常摘要；
- 每张状态卡都能带当前筛选条件跳转到明细页面。

首页包含“收益日历”卡片：

- 默认显示当前月，按已结束 Campaign 的闭合日展示已实现净 PnL；当前只扣除 USDT 手续费，
  资金费因账本没有权威事实而明确标记不可用；
- 同时显示本月累计 PnL、盈利日数、亏损日数和数据最后更新时间；
- 日界线首期固定为 Asia/Shanghai，并在卡片上明确标注；
- 点击某一天进入当日已结束 Campaign/交易轮次，点击卡片标题进入完整日历页；
- 历史数据即使 stale 仍展示，同时标注覆盖区间和缺失日期。

### 5.2 持仓与订单

页面使用页签组织，首期不提供人工平仓和任意下单：

- 当前持仓：方向、数量、均价、标记价、浮动 PnL、策略和账户；当前账本没有持仓开仓时间
  与 Campaign 归属，因此持仓时长和当前持仓 Campaign 明确标记不可用；
- 活动订单：状态、方向、价格、原始数量、已成交量、剩余量和创建时间；
- 历史订单：按环境、账户、策略、交易对和状态筛选；
- 详情展示订单、成交、持仓和策略审计事件之间的关联。

执行任务队列、网络重试和 `SUBMIT_UNKNOWN` 过程可在后续加入“执行状态”页签；只有后端提供
稳定查询接口后才展示，不能根据订单状态在前端猜测。

### 5.3 成交复盘

- 以完整 Campaign/交易轮次为主要浏览单位，同时允许查看底层 fills；
- 支持环境、账户、策略、交易对和时间范围筛选；结果和规范化退出原因因缺少权威字段，
  首期明确标记为不可用；
- 展示账本已有的成交、实际均价、手续费和净 PnL；信号价格、资金费、滑点和规范化退出原因
  在权威接口提供前明确标记不可用；
- K 线标记信号、委托、成交和退出位置；
- 事件时间线展示信号确认、风控、订单执行、成交和退出过程；
- 复用回测单笔 K 线复盘的图表和交互，避免维护两套图表逻辑。

### 5.4 绩效分析

绩效分析不包含收益日历，内部使用以下页签：

1. 绩效概览：净 PnL、已实现/未实现 PnL和交易成本；权益时序和回撤当前不可用；
2. 交易质量：胜率、盈亏比、期望值和 Profit Factor；持仓时长和盈亏分布当前不可用；
3. 交易对与分类：按交易对、Category、Subcategory 和方向分解结果；退出原因分组因缺少
   规范化权威字段，首期明确标记为不可用。

统一筛选条件包括运行模式、账户、策略、时间、交易对、Category/Subcategory 和方向。回测、
testnet、live 可以并排比较，但必须分开聚合和标注，不能混算。

统计以完整且已结束的 Campaign/交易轮次为样本，不以订单或单次 fill 为样本：

- 胜率 = 盈利轮次数 /（盈利轮次数 + 亏损轮次数）；平手单列；
- 盈亏比 = 平均盈利净额 / 平均亏损净额绝对值；
- 期望值 = 胜率 × 平均盈利净额 - 败率 × 平均亏损净额；
- Profit Factor = 总盈利净额 / 总亏损净额绝对值。

指标旁必须同时展示样本数、时间范围、成本口径和更新时间。没有亏损样本时盈亏比显示
“—”，不能显示为无穷大。样本不足只做提示，不自动停用策略。

### 5.5 回测复盘

保留现有研究记录和下钻结构：

- 研究记录及策略版本；
- 账户收益曲线和资金参数回放；
- 分析报表；
- 交易对表现；
- 单币交易记录；
- 单笔 K 线、事件和指标复盘。

回测页面必须显示历史数据覆盖、对齐修正、手续费和滑点假设。研究版本比较及回测/实盘
偏差分析属于后续功能。

### 5.6 策略风控

首期实际职责是“按策略管理分类准入”，不扩张为通用策略参数后台：

- 使用可搜索的策略选择器，避免自由输入策略 ID；
- 以 Category → Subcategory 树展示当前策略的分类开关；
- 明确区分“默认允许”和“显式关闭”；
- 展示关闭分类影响的交易对数量和最终有效交易池；
- 可查询单个交易对的判定过程和禁止原因；
- 修改时填写原因，使用乐观并发版本并展示审计记录；
- 关闭分类前提示相关未成交入场单会被撤销，已有仓位仍继续保护和退出。

准入判定严格复用数据层结果：

```text
交易所状态和生命周期
  -> 交易对全局准入
  -> 选定策略匹配 Category/Subcategory 的显式关闭规则
  -> 最终有效交易池
```

空策略配置、空分类配置或未分类交易对均不额外受限；任一匹配父分类或子分类显式关闭时，
阻止该策略新开仓。策略分类配置不能绕过全局禁用。

### 5.7 交易对管理

交易对管理只负责全局市场标的：

- 交易对、基础资产、计价资产、合约类型、交易所状态和生命周期；
- 上架时间、退市冻结、最后同步时间和数据覆盖状态；
- 全局准入开关及其修改原因、版本和审计记录；
- 按交易状态、全局状态、Category 和同步状态筛选；
- 表格保持简洁，Subcategory、精度、最小下单量和完整 metadata 放入详情弹窗。

页面删除“策略分类”页签，不显示策略选择器，也不修改策略准入。

### 5.8 分类管理

分类管理展示程序同步的 Binance 分类事实：

```text
Category
  -> Subcategory
     -> 关联交易对
```

- 支持层级树、搜索、展开/收起和关联交易对数量；
- 点击节点查看关联交易对和当前有效状态；
- 提供未分类交易对筛选；
- 展示数据来源、最后成功同步时间、stale 状态和覆盖范围；
- 不提供 Category/Subcategory 的人工创建、重命名、移动、删除或关联编辑。

未来若需要业务自定义分组，应新建与 Binance 事实分离的“自定义标签”模型，不能复用并覆盖
同步分类；在真实需求出现前不实现。

## 6. 三个管理模块的边界

| 模块 | 权威问题 | 可以修改 | 不能修改 |
|---|---|---|---|
| 分类管理 | 交易对属于什么 Binance 分类 | 首期只读 | 策略准入、全局准入、同步事实 |
| 交易对管理 | 平台全局是否允许该交易对 | 全局准入开关 | 策略分类开关、分类元数据 |
| 策略风控 | 某个策略是否排除某类交易对 | 选定策略的分类准入开关 | 全局禁用、分类事实、策略参数 |

三个页面都从 PostgreSQL 的统一数据层取数。前端不得自行复制分类关系、推测最终准入结果，
也不得通过局部开关绕过上游硬门禁。

## 7. 数据与 API 状态

可直接复用的现有能力：

- 订单、成交、持仓和 PnL 汇总查询；
- 交易对、Category/Subcategory 和交易对分类关联查询；
- 全局交易对准入、按策略分类准入及两类审计查询；
- 策略运行状态和账本健康；
- 回测研究、报表、收益回放、交易记录、事件和 K 线。

首期已经补齐并冻结的聚合能力：

- 按 Asia/Shanghai 自然日聚合的已实现净 PnL 和当日已结束 Campaign；
- 按策略、交易对、Category/Subcategory 和方向聚合的 Campaign 绩效指标；
- 平均盈利/亏损、胜率、盈亏比、期望值和 Profit Factor；
- 与执行 worker 一致的最终有效交易池及准入原因预览；

仍缺少权威数据、当前必须显示为不可用的能力：

- 资金费事实及包含资金费的完整净 PnL；
- 权益时序、回撤、持仓时长和盈亏分布；
- 规范化退出原因及其绩效分组；
- 按 Campaign 查询的实盘 K 线、信号价格和滑点；
- 若要展示执行任务和重试过程，需要独立任务状态查询，不能从订单表反推。

## 8. 通用易用性规则

- 环境、账户、策略和时间范围作为统一筛选上下文，并始终可见；
- 筛选条件写入 URL，返回列表时保留上下文；
- 总览卡片必须可下钻，不做只能观看的数字墙；
- 列表优先使用详情抽屉，复杂复盘再进入独立页面；
- 全局禁用、策略禁用、交易所不可交易和数据缺失使用不同状态及原因；
- 历史数据即使 stale 仍展示，并明确最后更新时间、覆盖区间和缺口；
- 影响新开仓或撤单的控制必须展示影响数量、后果、修改原因和审计记录；
- 不通过颜色单独表达盈亏或风险状态，文字、符号和颜色共同表达。

## 9. 分阶段顺序

首期实施状态如下：

1. 已完成：确认本文、同步决策和领域术语；
2. 已完成：拆分交易对管理，完成只读分类管理和策略分类准入；
3. 已完成：运行总览、首页收益日历、持仓与订单、成交复盘；
4. 已完成首期：Campaign 交易质量和交易对/分类分析；缺失数据维度继续标记不可用；
5. 后续评估：完整告警中心、执行任务可视化、高级风险限额、研究对比。

## 10. 明确不在首期范围

- Web 登录、身份认证和角色权限；
- Web 控制策略进程整体启停；
- 策略参数热更新、杠杆、仓位、回撤熔断等高级配置；
- 人工编辑 Binance Category/Subcategory；
- 手工任意下单、紧急平仓和未经确认的敏感操作；
- 根据胜率、盈亏比或 Profit Factor 自动启停策略；
- 为未来复用预建复杂规则表达式、审批流或自定义报表平台。
