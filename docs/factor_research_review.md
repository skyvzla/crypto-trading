# Factor Lab 架构评审与逼空因子研究方案

> 评审对象：`src/trading_platform/research/factor_lab/` 及 P0/P1 设计文档。
> 评审依据：代码阅读 + 近期平台数据实证研究（414 symbol、事件区间 1m bars 约 177 万根、550 个上涨插针事件）。
> 性质：纯评审与方案建议，不涉及代码修改。

## 一、总体评价

### 1.1 方向正确的部分

| 设计决策 | 为什么正确 |
|---|---|
| 研究/交易分离 | factor_lab 只读归档、不写策略路径；`strategies/spike` 不重复实现因子 |
| 事件驱动而非全量 bar 训练 | 避免把 99% 无事件样本灌进统计；`event_id = symbol:timestamp_ms` 可追溯 |
| 因果纪律 | `labels.py` 是唯一允许读未来数据的阶段；衍生品因子严格按 `available_time` 拼接 |
| 存储冻结原则 | 1s 归档 schema 冻结，CVD 等派生字段按需计算，避免磁盘失控 |
| cooldown 去重 | 同一波连续 spike 不被拆成大量高度相关样本 |
| scale-sensitive 隔离 | 原始 CVD/quote CVD 默认不进跨 symbol 比较，防止规模效应污染 IC |
| 分块执行 | 一个 symbol × 24h 时间块 → 临时 Factor Frame → 事件级 Dataset → 释放内存 |

### 1.2 核心结论

骨架合理，但有三个结构性缺口：

1. **缺对照机制**——所有分析都是"事件内条件分布"，没有无条件 base rate 对照，IC 无法区分"因子信息"与"事件本身的自回归性质"；
2. **只覆盖 TRIGGER 后阶段**——实证表明最有信息的信号在插针发生**之前**（前兆 lift 24x），而当前数据集从 spike 触发才开始采样；
3. **缺时间切分协议**——P1 全部样本参与统计，P2 上模型前没有 train/test 切分与 embargo 约定。

## 二、关键缺陷（按严重程度）

### 缺陷 1：缺负样本/对照机制，IC 无法解释为增量信息

当前 `analysis.py` 只在事件集合内部计算 `factor ↔ short_return` 相关。问题在于：spike 事件本身就是"暴涨后的极端状态"，均值回归是事件的先验属性。任何与涨幅正相关的因子都会对做空收益呈现正 IC——这是无条件均值回归效应，不是因子信息。

**实证证据：**

| 指标类别 | 对 ret15/ret60 的表现 |
|---|---|
| 全部 15 个技术指标 Spearman \|r\| | < 0.08 |
| 方向准确率 | 47–51%（随机水平） |
| 最强者：atr_ratio vs ret60 | r = 0.072（预测波动持续，非方向） |

单指标线性预测能力≈0。这意味着如果 TRIGGER 后某因子跑出好看的 IC，几乎必然来自条件 base rate 而非因子本身。

**要求**：每个因子的 IC 必须配 lift（相对无条件 base rate 的提升倍数）；无 lift 的 IC 不进入结论。

### 缺陷 2：只覆盖 TRIGGER 后，缺预警期（pre-event）研究

策略状态机规划了 `NORMAL→WARNING→ARMED→TRIGGER`，但数据集只支撑 TRIGGER 段。WARNING 段（"什么环境下容易爆发逼空"）没有任何数据集能回答。

**实证证据（1m 粒度前兆组合）：**

| 项目 | 数值 |
|---|---|
| 前兆定义 | bb_width > 5×rolling30 中位 & atr_ratio > 3×中位 & 上影线 > 2% |
| 触发后 5 根内出现插针概率 | **26.3%**（背景 1.089%，**lift ≈ 24x**） |
| 提前量 | 中位 4 根 1m |
| 召回率 | ~42% |
| 冗余性 | bbw 与 atr 相关 0.61；wick 独立增强 |
| 简化版 `atr>3x & wick>2` | 26.3% → ≈24.96%，损失极小 |

最有价值的信号出现在事件之前，而当前架构的采样起点是事件本身——研究方向与信息所在位置错位。

**补充实证（方向性）：**

| 前兆信号的用法 | 胜率 / 结果 |
|---|---|
| 做多 1h（事件区间内） | 87.2% |
| 做多 1h（事件区间外） | 52.8%（接近随机+尾部驱动） |
| 做空（entry=事件秒 close 追空） | 胜率 **12.7%**，盈亏比 0.29（灾难） |

该信号本质是"即将向上暴涨"预警，不是做空入场信号。labels.py 默认做空视角（`short_return/mfe/mae`）需要意识到这一点。

### 缺陷 3：样本自相关虚增 ICIR 置信度

cooldown 只有 60s，同一波上涨可以在数分钟到数十分钟内产生多个"独立"事件；同日多币种受 BTC 联动影响高度相关。月度分桶 ICIR（`analysis.py` 按 `%Y-%m` 分桶）假设桶内样本近似独立，实际有效样本数远小于表面 n，ICIR 显著高估。

**要求**：

- 按**天/事件簇**做 block bootstrap 再报 ICIR 置信区间；
- 增加 `relative_return_btc` 类因子剥离市场 beta，区分"币种自身行为"与"Beta 联动"。

### 缺陷 4：缺时间切分协议

P1 所有样本混合参与统计与后续调参。P2 上模型前若不先固定切分，任何因子/参数选择都存在隐性过拟合风险。

**要求（P2 前置条件）**：

- 按时间 70/30 切分 train/test，切分点固定后不可回调；
- embargo ≥ 最长持仓期（1h）：test 段起点向后推至少 1h，防止 train 尾部事件的前瞻窗口泄漏进 test。

### 缺陷 5：工程细节问题

| 问题 | 位置 | 影响 | 建议 |
|---|---|---|---|
| rolling 要求完全连续（如 `_continuous(group, 61)` + `min_periods=60`） | `factors/market.py` | 归档缺口处因子整片 NaN，且静默丢失 | Dataset 报告每因子的 NaN 率；NaN 率异常高的时段单独提示，而不是无声丢弃 |
| 月度分桶 ICIR 在短历史下为空 | `analysis.py` bucket_key=`%Y-%m` | 数据不足一个月时 ICIR 全部 NaN | 分桶粒度 fallback 到**按天**（min_bucket_samples 已有机制可复用） |
| entry=事件秒 close 追空的 base rate 预期很低 | `labels.py` 做空视角 | success 阈值 2% MFE@30m 在 12.7% 胜率背景下，绝大多数因子看起来都"无效"或都"有效"，取决于阈值巧合 | 报告无条件 base rate 作为参照系；考虑同时输出多头视角 label 以便交叉验证 |

## 三、改进设计：把逼空拆成三个独立研究问题

逼空不是单一预测问题，而是三个时间阶段、三种数据结构的问题。当前 factor_lab 只覆盖②。

| # | 阶段 | 研究问题 | 状态机对应 | 数据集形态 | 输出 |
|---|---|---|---|---|---|
| ① | 预警期（spike 前） | 什么状态容易爆发逼空？ | WARNING | pre_event_dataset：以前兆组合（如 `atr>3x & wick>2%`）为事件定义，label = 未来 N 根内是否出现 spike | 环境因子清单：波动率压缩、OI 积累、funding 极值、箱体突破时长等 → 用于预热挂单/universe 收缩 |
| ② | 进行中（spike 中） | 哪些上涨不可持续？ | ARMED/TRIGGER | 现有 event_dataset | 订单流衰竭、CVD 背离、速度衰减 → 用于确认放弃追空/等待反转 |
| ③ | 确认后（spike 后） | 反转概率与路径如何？ | EXIT | 现有 labels（MFE/MAE 分布） | 止损带宽、止盈位置、仓位参数 |

具体动作：

- 新增 **pre_event_dataset**：事件定义改为前兆组合而非 spike 本身；label 为二值（未来 N 根内 spike 与否）+ 回归（距 spike 的 bars 数）。这直接复用现有 dataset/event/labels 流水线骨架，只是换事件函数与 label 函数。
- ①的答案回答"何时开始盯"、②回答"这笔能不能做"、③回答"怎么出场"。三者因子集可以重叠，但评估协议必须分开。

## 四、逼空因子参数研究方法论（五步法）

当前流程是"算 IC → 排序"。替换为以下闭环：

### 第 1 步：地形图（base rate 表）

以 rise幅度 × vol_multiple × duration 三维分层，统计每格的事件数与后续反转 base rate。

- 先知道哪里**有样本**、哪里 **base rate 高**；
- 后续一切 lift 都相对这张表计算；
- 避免在样本稀疏格子里得出伪结论。

### 第 2 步：单因子 lift 扫描

每个因子在各分位上计算 lift = 条件胜率 / 该层 base rate。

- 淘汰规则：**lift < 1.3 或 n < 100 直接出局**；
- IC 仅作参考（实证已证明单指标 IC≈0，不能作为主排序键）。

### 第 3 步：显式规则组合

取第 2 步 top-10 因子两两组合（分位切点），构建条件概率表。

- 规则深度 ≤ 3，保持可解释（与现有 scoring.py 的人工评分体系兼容）；
- 组合条件概率映射为 scoring 权重建议，而不是黑盒模型输出。

实证支持：三因子前兆组合 lift 24x，而其中 bbw 与 atr 相关 0.61 属冗余——组合的价值在互补不在堆叠，相关矩阵去冗余（correlation.py 已有）应前置到本步骤。

### 第 4 步：敏感性检验

对通过第 3 步的组合做阈值 ±20% 扰动。

- 表现排名不稳定的组合丢弃（说明结论由某个巧合阈值驱动）；
- 参数只在 train 段选择，test 段只允许跑一次。

### 第 5 步：成本敏感终评

期望 = P(win)×avg_win − (1−P)×avg_loss − 手续费 − 滑点。用期望排序，不用 IC 排序。

实证支持：

| 场景 | ret 中位 | 含义 |
|---|---|---|
| 事件区间外触发的后续收益 | **+1.6%** | 扣 taker 双边费用后所剩无几，多数"统计显著"因子过不了成本关 |

另附真假插针过滤层的定位（1s 级）：`vol_ratio 高(5s量/前60s中位) & pre_bbw 低(前60s波动) & vwap 中段` 把真回落率从 30.9% 提到 50.5%，但期望归零——**只能做过滤层，不能单独交易**。这类结论只有走完第 5 步才能得到正确定位。

### 衍生品慢因子的单独定位

OI / funding / 多空比是慢周期环境因子（5m 粒度、available_time 滞后），它们回答的是：

> **哪些币容易逼空（选 universe）** —— 不是 **何时入场（timing）**

不应与秒级订单流因子放在同一个 IC 排名里竞争。建议在 report 中按 horizon 层分组呈现（horizon.py 的 half-life 字段已具备支撑此分组的能力）。

## 五、落地路线图

### P1.5（本次）：factor_lab 增加 lift 分析模块

| 模块 | 内容 | 对应缺陷 |
|---|---|---|
| 地形图 | rise × vol_multiple × duration 分层 base rate 表 | 缺陷 1 |
| lift 扫描 | 单因子 lift + n，淘汰线 lift<1.3 / n<100 | 缺陷 1 |
| 规则组合 | top-10 两两分位组合条件概率表，深度≤3 | 方法论第 3 步 |
| 敏感性 | 阈值 ±20% 扰动稳定性检验 | 方法论第 4 步 |
| 成本终评 | 期望收益排序替代 IC 排序 | 方法论第 5 步 |

### P1.9：数据层补强

| 项 | 内容 | 支撑实证 |
|---|---|---|
| pre-event 数据集 | 前兆组合为事件定义，label=未来 N 根内是否 spike；简化定义 `atr>3x & wick>2%` 起步 | 前兆 lift 24x、召回 42% |
| relative_return_btc | 剥离 BTC beta 后再评因子 | 同日多币联动 |
| 按天分桶 fallback | ICIR 分桶粒度 %Y-%m → %Y-%d | 短窗口 ICIR 为空 |
| NaN 率报告 | Dataset 汇总各因子 NaN 占比 | 缺口静默丢样本 |

### P2 前置条件（未满足不得开模）

| 项 | 标准 |
|---|---|
| 时间切分 | 按时间 70/30，切分点冻结 |
| Embargo | test 段起点 ≥ train 末尾 + 最长持仓期 1h |
| Block bootstrap ICIR | 按天/事件簇重采样给出置信区间 |
| 成本模型接入 | 终评一律含手续费+滑点 |

### 引用实证小结

| 建议 | 依据 |
|---|---|
| 必须配 lift，不信裸 IC | 15 指标 \|r\|<0.08，准确率 47–51% |
| 新增 pre-event 研究 | 前兆 24x lift、提前量中位 4 根 |
