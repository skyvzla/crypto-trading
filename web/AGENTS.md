# Web 开发约定

## 排版规范

Web 页面统一使用 `web/src/styles/base.scss` 中的语义化排版 Token。禁止在组件样式中新增 `10px`、`12px`、`13px` 等低于 14px 的可见文字字号，也不要用 `xs/sm/md` 表达业务语义。

标准字号（最小 14px）：

| 语义     | 用途                          | 建议字号              |
| -------- | ----------------------------- | --------------------- |
| 页面标题 | 页面主标题                    | 22px / 30px           |
| 区块标题 | 卡片、详情区块标题            | 18px / 26px           |
| 主内容   | 事件名称、关键数值、主要指标  | 16px / 24px           |
| 次要内容 | 普通参数、辅助说明            | 15px / 22px           |
| 备注信息 | 时间、状态、参考值、描述      | 14px / 20px           |
| 技术字段 | 参数 key、英文 event_type、ID | 14px / 20px，等宽字体 |

字重统一为：页面/区块标题 600，主要内容和主要指标 500～600，普通内容和备注 400。中英文不得仅因语言不同而缩小字号；技术字段可以使用等宽字体，但字号仍不低于 14px。

## 代码格式与可读性

- Web 代码首先服务于人工阅读，不得为了减少文件行数压缩模板、样式或脚本。
- Vue/HTML/JSX/TSX 中禁止在同一行连续书写多个标签；父子标签、兄弟标签和具名模板应按层级换行并保持清晰缩进。
- 标签包含多个属性、事件或较长表达式时，属性应逐行排列；复杂模板插值应换行或提取为有意义的计算属性。
- 短文本和短插值应与标签保持在同一行，例如 `<span>{{ text }}</span>`；若表达式过长，应先提取为计算属性，而不是把开始标签、文本和结束标签拆成三行。
- 复杂动态渲染、类型化 render function 或 Vue 模板表达能力明显不足时可以使用 JSX/TSX；普通页面结构优先保持现有 Vue SFC 写法，不因个人偏好混用两套表达方式。
- TypeScript 的长对象、数组、函数调用及条件表达式应按语义分行，避免横向堆叠；命名应表达业务含义，不能以格式紧凑替代清晰结构。
- 修改 Web 文件后必须在 Node 容器中执行 `npm run format`；提交前执行 `npm run format:check`，不得提交未格式化的代码。
- 格式化只能改变代码布局，不得借机覆盖用户正在进行的业务改动；格式化后仍需检查 diff，确认没有无关文件或逻辑变化。

## 通用响应式与组件约定

- 颜色、字号、行高、字重优先复用全局 Token；组件不得为同一语义建立局部变体。
- 响应式断点优先依据实际内容容器宽度；需要适配不同页面时，优先使用容器查询或组件自身的响应式配置，不要假设浏览器视口就是内容宽度。
- 内容密度较高的表格、详情和卡片应允许换行、堆叠或横向滚动；不得通过缩小字号低于全局最小值来换取空间。
- 布局改动至少补结构、响应式配置和长内容换行/溢出回归测试；有条件时检查 390、768、1024、1600px 尺寸。
- 页面专属的信息架构、字段顺序和业务展示规则应写在对应组件和测试中，不放入本文件。
- Web 修改后使用 Node 容器执行 `npm test`、`npm run build`；不要启动宿主机 Vite 作为交付或验证环境。
- Web 静态产物由 `trading_platform-ledger` 镜像构建并由 Compose 的 `ledger` 服务提供。修改后必须重新构建并重启 `ledger`，检查 Compose 状态、`/api/v1/health` 和首页 HTTP 状态。
